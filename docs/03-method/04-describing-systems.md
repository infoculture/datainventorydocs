# Описание системы и ресурса

Каждый источник на карте описывают карточкой из десяти полей. Пять из них обязательны: название, владелец, тип, статус доступности и дата проверки. Если сведение найти не удалось, пишут «не установлено» и где искать дальше. Честный пропуск полезнее догадки: при следующем обновлении сразу видно, что проверять.

## Карточка источника

| Поле | Что писать | Обязательно |
|------|------------|:-----------:|
| **Название** | Официальное название; сокращение — в скобках | да |
| **Тип** | система, ресурс, набор данных, сайт или группа ([одинаковый уровень подробности](#одинаковый-уровень-подробности)) | да |
| **Владелец** | Орган власти или организация, которая ведёт источник | да |
| **Правовое основание** | Закон, постановление или пункт положения, по которому источник создан | |
| **Уровень** | федеральный, региональный, муниципальный; для негосударственных — «коммерческий», «международный» | |
| **Ресурсы** | Для системы — какие ресурсы в ней есть; для ресурса — в какой системе он ведётся | |
| **Адрес** | Ссылка на сайт, раздел открытых данных или программный интерфейс | |
| **Статус доступности** | открытые данные, неструктурированные сведения, с ограничениями, закрыто, не установлено | да |
| **Основание статуса** | Ссылка или документ, которые подтверждают статус | |
| **Дата проверки** | Месяц и год, когда сведения проверены | да |

Отдельно полезно записывать, **откуда известно** об источнике: реестр ГИС, план информатизации, госконтракт, сайт владельца, эксперт. Это не поле карточки для читателя, а заметка для того, кто будет карту обновлять.

## Пример

Карточка системы с карты по Росавиации (глава [«Карта по полномочиям»](../02-map-types/04-authority-maps.md)). Заполнено то, что видно на карте; остальное помечено и снабжено подсказкой, где искать.

| Поле | Значение |
|------|----------|
| Название | ФГИС ИАС «Поиск» |
| Тип | система |
| Владелец | Росавиация |
| Правовое основание | не установлено — искать в реестре ФГИС и в положении о Росавиации |
| Уровень | федеральный |
| Ресурсы | дежурные поисково-спасательные воздушные суда; региональные поисково-спасательные базы; аэродромы дежурства поисково-спасательных воздушных судов; аэронавигационная информация, влияющая на проведение поисково-спасательных работ; зоны (районы) ответственности за поисково-спасательное обеспечение; авиапроисшествия |
| Адрес | не установлено |
| Статус доступности | не установлено |
| Основание статуса | — |
| Дата проверки | — (карта Росавиации не датирована) |

Даже такая карточка уже полезна: она говорит, что у системы шесть ресурсов, и подсказывает, что делать дальше.

## Система, ресурс, набор данных или сайт

Тип источника определяют по трём вопросам.

1. **Есть ли у объекта владелец и основание для создания?** Если да — это система. У государственной информационной системы основание всегда есть: она создаётся на основании закона или акта, перечисленного в статье 13 закона № 149-ФЗ, для реализации полномочий (статья 14).
2. **Это перечень однотипных записей?** Реестр лицензий, база аварий, список аэродромов — ресурс. Ресурс всегда ведётся в какой-то системе, даже если она неизвестна.
3. **Это файл или программный интерфейс, который можно скачать или вызвать?** Тогда это набор данных — опубликованная часть ресурса.

Сайт — ни то, ни другое, а витрина. За сайтом ищут систему: в разделе «О системе» или «Документы», в реестре ГИС по адресу, в госконтрактах по названию сайта, в [реестре государственных доменов](../04-sources/01-overview.md). Если найти не удалось, сайт записывают как источник с типом «сайт» — это честнее, чем придумать систему.

Подробнее о различиях — в главе [«Из чего состоит карта данных»](../01-basics/03-anatomy.md#система-ресурс-набор-данных-и-сайт).

## Один источник под разными именами

Один и тот же источник встречается под разными именами: «реестр юридических лиц», «ЕГРЮЛ» и адрес egrul.nalog.ru — это один ресурс ФНС России. Если записать его трижды, карта покажет три источника там, где есть один, и при обновлении придётся править три строки. В атласе так случилось с порталами открытых бюджетов: на картах [«Государственные финансы»](../06-atlas/02-public-finance.md) и [«Образование»](../06-atlas/05-education.md) одна группа источников записана тремя разными названиями, и при переносе в данные она стала одним источником с синонимами.

Чтобы этого не случилось:

- **заведите идентификатор** — короткое имя латиницей или номер строки, и связывайте вопросы с ним, а не с названием;
- **записывайте синонимы** в отдельную колонку: другие названия, сокращения, адреса;
- **перед добавлением ищите** по синонимам и по адресу, а не только по названию;
- **источники, которые повторяются от карты к карте**, описывайте один раз в общем списке и ссылайтесь на него.

## Одинаковый уровень подробности

На одной карте источники должны быть описаны с одинаковой подробностью. На карте [«Нефть и газ»](../06-atlas/03-oil-and-gas.md) рядом стоят конкретный адрес lic.rfgf.ru и «сайты нефтяных компаний». Первое можно проверить, второе — нет.

Если перечислить источники поштучно невозможно, группу записывают одной строкой с типом «группа» и поясняют, что в неё входит и почему она не раскрыта: «годовые отчёты нефтяных компаний — публикуются каждой компанией на своём сайте, список компаний — в источнике X». Так читатель видит, что это осознанное упрощение, а не пропуск.
